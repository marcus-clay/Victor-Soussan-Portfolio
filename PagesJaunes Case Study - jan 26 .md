## Cross-Platform Local Search Experience

## (6000 words)

#### Introduction

From 2014 to 2016, I worked as a Product Designer and later UI Team Lead at PagesJaunes,
one of France's largest digital directories. At its peak, the mobile app reached 22 million
downloads and served 300,000 daily users. This was an intense design period where we
needed to modernize legacy systems, ensure feature parity across iOS, Android, and web
platforms, and create experiences that felt personal, fluid, and robust.

Working alongside UX, marketing, and OS-specific engineering teams, I led the redesign of the
PagesJaunes apps for iOS, Android, Android Wear, and responsive web. The work was
systematic, hands-on, collaborative—and deeply constrained by business timelines and
platform limitations. We had to move fast, while keeping design quality high.


#### 1. The Brief and the Landscape

At the time, PagesJaunes was transitioning from a legacy search experience rooted in printed
directories to a mobile-first, cross-platform strategy. The product needed to:

```
● Reinvent its core homepage and search interaction on mobile.
● Introduce a new onboarding flow.
● Create a coherent look and feel across iOS, Android, and web.
● Support new platform opportunities like Android Wear.
```
We needed to preserve trust with a very large user base, while building new paths for usage
and retention.

**Placeholder – Visual:** Stats showing app usage, growth, downloads.

#### 2. Redesigning the Homepage

###### Starting from Intent, not Listings

The old homepage showed two big search fields: Who / Where. It worked—but didn’t feel smart,
or welcoming. Inspired by messaging apps and personal assistants, we moved toward a more
conversational design.

```
"Bonjour, de quoi avez-vous besoin ?"
```
This friendly phrase set the tone. It brought warmth and humanity to a utility-first tool.

###### Professional Proximity as a Visual System

We designed contextual homepage backgrounds, featuring professionals in their environments:
the baker, the mechanic, the florist. These backgrounds rotated based on category relevance.

```
● Created art direction rules for portraiture, lighting, and framing.
● Aligned content with search intent (e.g. show a doctor image if user is near a medical
zone).
```
**Placeholder – Visual:** iOS and Android homepage with contextual photos.

**Placeholder – Visual:** 8 homepage image variations.


###### Interaction Simplified

We reworked the top bar, tabs, and filters to prioritize the query field. The search itself became
the protagonist.

```
● Reduced visual clutter
● Unified tab language across OS
● Enhanced CTA contrast and accessibility
```
#### 3. First-Time Use and Onboarding

###### Mobile OS Constraints

We were launching v8.0 of the PagesJaunes mobile apps. At this scale, users needed help
discovering the updates. We designed short, non-blocking animations triggered at first launch.

```
● iOS: Leveraged CAAnimation to animate app walkthrough on launch screen.
● Android: Used Activity transitions to onboard with Material cues.
```
**Placeholder – Visual:** Video or screenshots of onboarding animation (iOS & Android).

###### Goals

```
● Reduce support requests about navigation
● Boost feature discovery (e.g. Favorites, Maps)
● Increase retention in week 1
```
We iterated through 3 storyboard versions, tested 1:1 with users in our Paris lab.

#### 4. Maps and Navigation UI

###### Geolocation, But Smarter

One of our main goals was to make it faster to find a professional and get directions. The map
experience needed to:

```
● Load quickly on all networks (including 3G)
● Let users pick between multiple nav apps (Waze, Google Maps, etc.)
● Provide real pedestrian route previews
```

We integrated with the Mappy API and designed our own directions UI on top.

**Placeholder — Visual:** Map flow on iPhone and iPad.

###### Tablet Design

On iPad, the map experience was completely redesigned with split views, contextual cards, and
persistent routing.

```
● Emphasized route clarity
● Used native iOS split views to adapt for landscape
● Supported accessibility features (dynamic type, VoiceOver)
```
**Placeholder — Visual:** iPad directions view and accessibility grid.

#### 5. UI System and Cross-Platform Consistency

###### Design System Foundations

We started building a component system to bring UI consistency across:

```
● PagesJaunes.fr (desktop and mobile)
● iOS app
● Android app
```
We created specs for:

```
● CTA styles, color usage, and iconography
● Status indicators (open/closed hours)
● Map annotations and tooltips
```
These were shared via Zeplin and PDF kits—pre-Figma era tools.

**Placeholder — Visual:** Design system tooltip styles (before/after).

#### 6. Android Wear Prototype

This was an experimental, forward-looking project. We imagined a micro-UX:

```
"I want to find a restaurant around me and call. Or get guided there. From my
watch."
```

We designed:

```
● A compact card UI with ratings, categories, contact CTA
● Dark mode & ambient mode views
● Navigation handoff to mobile
```
**Placeholder — Visual:** Android Wear flows and screens.

#### 7. Team Collaboration & My Role

This project was impossible to pull off alone. We were 4 designers (including myself), 2 iOS
devs, 2 Android devs, backend, marketing, and PO.

I led:

```
● UI direction and component specs
● iOS interaction design and animation logic
● Design team rituals and mentoring
● Executive presentations (User Club Day, roadmap reviews)
```
I worked hand-in-hand with:

```
● Backend for API payload shaping (e.g. open hours structuring)
● Mobile OS teams to adjust scroll limits, gestures, animation priorities
● Marketing for homepage image guidelines
```
We ran weekly crits and retros. Fast feedback loops, tight alignment.

#### 8. Outcomes and Impact

We measured impact in both quantitative and qualitative terms:

###### Quantitative:

```
● +18% increase in homepage search CTR
● +24% feature discovery (Favorites, Directions)
● -20% support tickets about app navigation
```
###### Qualitative:

```
● Higher App Store ratings (avg 4.2 → 4.5)
```

```
● Better feedback from User Club Day demos
● Internal team more aligned around cross-platform work
```
It also set the foundation for a future design system, which later teams used and expanded.

#### 9. Learnings and Reflections

This work taught me the value of:

```
● Designing for legacy users with care
● Working across OS without duplicating effort
● Prototyping early to spot navigation and animation pitfalls
● Being humble about constraints, and creative about what can still be improved
```
PagesJaunes was not a trendy app. But it was used by millions. That scale taught me how to
design with precision, empathy, and a bias toward clarity.

#### 10. What I’d Do Differently Today

```
● Use a Figma component library and Zeroheight system from day 1
● Add analytics events to better track specific interactions (e.g. first map zoom, tab
switches)
● Set up qualitative feedback loops in-app (mini surveys, exit interviews)
● Build more motion guidelines upfront (to scale animations properly)
```
#### Final Thoughts

This was an intense 2-year chapter. It shaped a lot of my thinking around mobile design at
scale, system consistency, and the quiet details that make a search product feel human.

We didn't solve everything. But we made a very big product feel a little bit closer, a little bit
faster, and a lot more welcoming.
