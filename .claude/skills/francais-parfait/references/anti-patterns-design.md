# Anti-patterns design et produit

Jargon startup francophone mal employé, anglicismes de l'écosystème tech/design, et formulations artificielles fréquentes dans le contexte produit.

## 1. Jargon startup francisé de force

| Interdit | Préférer | Contexte |
|---|---|---|
| pivoter (stratégie) | changer d'orientation, réorienter | Calque direct de « pivot » |
| itérer dessus | améliorer progressivement, affiner | Calque de « iterate on » |
| scaler / passer à l'échelle (abusif) | croître, se développer, étendre | Acceptable uniquement en contexte technique d'infrastructure |
| le delivery | la livraison, la mise en production | Anglicisme brut |
| un use case | un cas d'usage | Acceptable en contexte très technique, sinon franciser |
| un pain point | un irritant, une friction, un problème | Anglicisme brut |
| le time-to-market | le délai de mise sur le marché | Utiliser l'anglais uniquement si le contexte l'impose |
| la North Star | l'objectif directeur, la vision | Métaphore anglophone |
| un quick win | un gain rapide, une amélioration immédiate | Anglicisme brut |
| ownership (prendre l'ownership) | prendre en charge, assumer la responsabilité | Anglicisme brut |
| un stakeholder | une partie prenante | Systématiquement franciser |
| le scope | le périmètre | Systématiquement franciser |
| le backlog | le carnet de commandes, la liste des tâches | Acceptable tel quel en contexte Agile strict |
| un workshop | un atelier | Systématiquement franciser sauf nom propre |
| un framework | un cadre, un modèle, une méthode | Franciser sauf contexte code |
| actionable | exploitable, applicable | Calque direct |
| le wording | la formulation, le libellé | Anglicisme brut |
| un insight | un enseignement, une observation, un constat | Systématiquement franciser |
| la data (au singulier) | les données | « La data » est un anglicisme |
| un deliverable | un livrable | Franciser |
| onboarder un utilisateur | accueillir, accompagner la prise en main | Anglicisme brut |
| le run (opérations courantes) | l'exploitation, les opérations courantes | Anglicisme brut |
| le build (phase de construction) | la construction, le développement | Anglicisme brut |

## 2. Formulations design/UX artificielles

| Interdit | Préférer | Pourquoi |
|---|---|---|
| L'utilisateur est au cœur de notre démarche | (supprimer, c'est du remplissage) | Phrase vide, tout le monde le dit |
| Une expérience fluide et intuitive | Décrire concrètement ce qui la rend fluide | Formule creuse |
| Design thinking (comme solution magique) | Expliquer la méthode concrète appliquée | Buzzword vidé de sens |
| Centré utilisateur / user-centric | Expliquer concrètement l'implication des utilisateurs | Devenu un cliché |
| Seamless (en français) | Fluide, sans rupture, cohérent | Anglicisme |
| Frictionless | Sans friction, sans obstacle | Anglicisme |
| Le parcours utilisateur est pensé pour... | Décrire les choix de conception concrets | Formulation vague |
| Nous avons designé... | Nous avons conçu... | Anglicisme verbal |
| Le look and feel | L'apparence, le rendu visuel, l'identité graphique | Anglicisme |
| Un design system robuste | Décrire ce que le système contient et résout | « Robuste » est vague |

## 3. Formulations produit creuses

| Interdit | Pourquoi |
|---|---|
| Créer de la valeur pour l'utilisateur | Dire quelle valeur concrètement |
| Maximiser l'impact | Quel impact, mesuré comment |
| Aligner les équipes | Sur quoi, par quel moyen |
| Être data-driven | Décrire les données utilisées et les décisions qu'elles informent |
| Avoir une vision produit claire | Énoncer la vision au lieu de dire qu'elle est claire |
| Passer en mode agile | Décrire les pratiques concrètes adoptées |
| Prendre du recul | Supprimer ou expliquer ce que l'analyse a révélé |
| Monter en compétence | Former, apprendre, se spécialiser |
| Aller chercher de la croissance | Acquérir des clients, augmenter le chiffre d'affaires |

## 4. Structures rhétoriques design/produit typiques LLM

| Interdit | Correction |
|---|---|
| Le design, ce n'est pas rendre les choses jolies. C'est résoudre des problèmes. | Supprimer. Cliché absolu. |
| L'UX n'est pas un luxe. C'est une nécessité. | Supprimer ou reformuler avec des données. |
| Un bon design est invisible. | Cliché. Développer le propos concret. |
| Le meilleur code est celui qu'on n'écrit pas. | Cliché. |
| Les utilisateurs ne savent pas ce qu'ils veulent. | Cliché. Nuancer avec la méthodologie. |
| Move fast and break things. | Cliché. Décrire la méthodologie réelle. |

## 5. Règle générale

En contexte design/produit, préférer systématiquement :
- La description concrète au buzzword
- Le résultat mesurable à l'intention vague
- Le français au franglais, sauf quand le terme anglais est le standard absolu du métier (ex : « sprint », « CSS », « wireframe » sont acceptables)
- La simplicité lexicale à l'inflation terminologique
